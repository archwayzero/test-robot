How the playthroughs work: `record.py` starts the scene without `-- --automation`, so `Core.automation` is **null**
in recordings (F5). The playthrough scenes (`godot/tests/e2e/playthrough_*.tscn`, base `playthrough_base.gd`)
therefore drive the game the way a player does:
- `Input.action_press`/`action_release` on `GameActions`;
- `Input.parse_input_event` touches for mini-map taps and camera-orbit drags.

They read the game only through `GameMain`'s public accessors. Because this is not a test run, they save to
`user://`, the sandbox user's Godot data dir. Slot 0 is deleted first so each video starts from a fresh game.

## Findings
| # | Severity | Finding | Where | Suggested owner |
|---|---|---|---|---|
| F1 | **Fails E11** | The cloud envelope rounds floats. `make_envelope()` calls `JSON.stringify(JSON.from_native(envelope, false))` with the default `full_precision = false`, so doubles are written with about 15 significant digits. The cloud copy then differs from `Core.state` and from the local save, for example `player/yaw` by about 3e-15 rad. A cloud-restored game is not bit-identical to the save. Gameplay impact is negligible, but it breaks TEST_PLAN E11's "snapshot equals the state". Suggested fix: `JSON.stringify(JSON.from_native(envelope, false), "", true, true)`, plus a unit test with a non-representable float such as a float32 yaw. | `godot/modules/cloud_save/internal/auto_save_impl.gd:148` | module-dev (cloud_save) |
| F2 | Minor, not failing | The autosave throttle fires 1 frame early: 299 frames (9.967 s) after the first save, not 300. `_since_last_save` is reset during the physics step, and then the same frame's `_process` delta is added. E11's tolerance (299-302 frames) accepts this. | `godot/modules/cloud_save/internal/auto_save_impl.gd` (`_save()` / `_process()`) | module-dev (cloud_save), optional |
| F3 | Test-hook gap | The public `Minimap` has no read access to what it draws. E8/E9 call the implementation's `get_marker_cell()` / `get_cell_color_model()` duck-typed (`has_method` + `call`). Request: add `get_marker_cell() -> Vector2i` and `get_explored_drawn_cells() -> Array[Vector2i]` (or the colour model) to the public interface. | `godot/modules/minimap/public/minimap.gd`; impl `godot/modules/minimap/internal/minimap_impl.gd:103,108` | orchestrator |
| F4 | Test-hook gap | The public `TouchControls` does not expose button positions. E15 hard-codes Jump centre = (w-108, h-92) and Stance centre = (jump.x-133, h-77), taken from the implementation constants, so a layout change would break E15 silently. Request: `get_jump_rect() -> Rect2` and `get_stance_rect() -> Rect2` (viewport coordinates), like `Minimap.get_small_rect()`. | `godot/modules/touch_controls/public/touch_controls.gd`; constants `godot/modules/touch_controls/internal/touch_controls_impl.gd:16-20,89-96` | orchestrator |
| F5 | Tooling gap | `record.py` launches the scene without `-- --automation`. As a result, `Core.automation` is null in gameplay videos, so playthroughs cannot use the automation API that TEST_PLAN prescribes, and videos write saves to the real `user://` instead of `user://automation/`. Request: pass `-- --automation` to the Godot command (or add an option for it). | `tools/qa/record.py:66-68` | orchestrator |
| F6 | Visual (video) | In CROUCH and CRAWL cells the camera's spring arm collapses onto the player, so the capsule fills most of the screen and the passage is hard to see. The human should judge it in `stances.mp4` at 00:16-00:25 and 00:32-00:47. Suggestion: under low ceilings, lower the pivot and flatten the pitch instead of only shortening the arm. | `godot/modules/player/internal/player.gd` (`_update_rig`, `ARM_LENGTHS`, `DEFAULT_PITCH`) | module-dev (player) |
| F7 | API note | E11/E13 call `AutoSave.setup()` a second time to swap in the fake backend. The public docs say "Call once", but the implementation simply replaces the backend. If that ever changes, E11/E13 need another seam, for example a `GameMain` test hook to choose the backend before boot. Also, `FakeCloudBackend.pushes` is not public, so E11 checks the envelope via `pull()` at each `autosaved`. | `godot/modules/cloud_save/public/auto_save.gd`, `godot/modules/game/internal/game_main_impl.gd` (`_boot`) | orchestrator |
| F8 | Info | `Automation.drag()` always lifts the finger at the end, so a held deflection cannot be sampled with `drag()` alone. E14 uses `touch()` + `inject_event(ScreenDrag)` for the held phase, and also runs a full `drag()`. | `godot/modules/core/public/automation.gd` | orchestrator (optional: `drag(..., release := true)`) |
| F9 | Info | The runner's `--report` with a relative path fails ("cannot write report") because `FileAccess` does not resolve it against the repo root. Use an absolute path. | `godot/addons/test_runner/run.gd` (`_write_report`) | orchestrator |
