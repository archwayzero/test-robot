## What changed in the tests (godot/tests/e2e/ only)
- **Only public APIs are used now.**
  - E8 and E9 call `Minimap.get_marker_cell()` and `get_cell_color_model()` directly, with no duck typing. E9 also
    checks that every drawn cell has a non-black colour.
  - E11 decodes with `AutoSave.decode_cloud_payload()` and does no format-specific parsing.
  - E15 taps `get_jump_rect().get_center()` and `get_stance_rect().get_center()`. It also checks that both rects are
    on screen and do not overlap.
  - Grep for module internals, `has_method` / `call`, and `/root/` paths: none left.
  - Two engine-API uses remain, and neither is a module API or node path:
    - E13 walks `get_tree().root` to list visible CanvasItems and Windows, to prove that no error UI appears.
    - The playthroughs read `get_window().size` to convert raw drag events.
- **Playthroughs now run in Core automation mode.**
  - `playthrough_base.gd` refuses to run and quits (exit 2) if `Core.automation` is null or
    `CoreAPI.user_data_dir()` is not `user://automation/`.
  - Otherwise it calls `set_seed(1)` and `set_fixed_timestep(60, 30)`.
  - All input goes through `Core.automation`: `press_action` / `release_action` / `tap_action`, `touch`, and
    `inject_event` for the camera-orbit drags. Before, they used `Input.*` directly.
- **E11 is stricter.** The decoded snapshot must equal `Core.state.snapshot()` at save time both with `==` and as
  identical `var_to_bytes()` output (bit-exact floats, same Variant types). The test also checks that an invalid
  payload decodes to `{}`. The throttle gap must now be at least the full interval: 300-302 frames, where T010
  allowed 299-302.
- **New checkpoint guard against N1 (`e2e_base.gd`).**
  - Every test must reach `checkpoint("end")`.
  - The conditional and loop bodies that hold assertions declare their expected hit counts (E3 tries, E4 landing,
    E5 8 angles, E11 gap / 2 payloads / latest, E13 result).
  - `after_each()` runs in its own stack frame. It fails the test if a checkpoint was missed.
  - Verified with a throw-away negative test (deleted): a missing checkpoint fails the test.
- The T010 `.uid` files for the e2e scripts are now committed.

## New findings
| # | Severity | Finding | Where | Suggested owner |
|---|---|---|---|---|
| N1 | **Test reliability** (silent skipped assertions) | **Godot 4.7.2 skips `if` bodies after `await Core.automation.wait_until(<lambda capturing a local>)`.** The condition evaluates true, but the body does not run. In E11, inlined, it also produced `Cannot convert argument 1 from Object to bool` on the first bool argument in a loop (`Dictionary.is_empty()` gave typeof 24). The repro is below. Narrowing: the same code runs correctly after `await get_tree().process_frame`, with no await, or with a predicate lambda that captures nothing. T010's E11 had its gap check in exactly such an `if` body, so T010's gap assertion may not have run. Its 299-frame figure came from the printed frames. **Mitigation in this run:** E11's post-await checks are in plain helper functions, and the checkpoint guard (see above) makes a skipped block fail the test. **Request:** triage whether the cause is `wait_until` in core or the GDScript VM (report upstream if it is the VM). Module tests that use `wait_until` with capturing lambdas may be affected too: consider adding a TEST_PLAN note or a runner-level guard. | `godot/modules/core/internal/automation/automation_impl.gd:128` (`wait_until`) or the GDScript VM; affected pattern in any `*_test.gd` | orchestrator (triage) -> module-dev (core) or upstream |
| N2 | Visual, minor (human to judge) | In the CRAWL passage the capsule's top edge appears cut flat and straight (`stances.mp4` 00:33-00:40). This could be near-plane clipping of the player mesh or the ceiling insert occluding it. It does not block the view ahead, and the player is not faded at this distance (the fade only applies closer than ~0.6 m). | `godot/modules/player/internal/` (camera rig) | module-dev (player), only if the human considers it a defect |
